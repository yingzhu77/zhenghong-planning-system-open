# 计划系统

采用 [MIT 许可证](LICENSE) 的公开源码仓库。包含住宅与商业计划填报、计划总览、项目详情、档案维护、历史评价、富文本和附件服务，采用原生 JavaScript、Node.js/Express、PostgreSQL 与 Docker Compose。第三方组件及品牌说明见[许可与素材说明](THIRD_PARTY_NOTICES.md)。

同事或Agent接续开发请先读[协作与本地预览](CONTRIBUTING.md)：克隆main，在独立开发分支修改，本地确认效果后提交PR，由维护者审查后发布。公开clone可独立启动匿名演示，不需要生产账号、备份或私有交接文档。

直接交给同事的Codex执行，可复制[一份完整交接提示词](docs/AGENT_HANDOFF.md)，已包含环境安装、匿名数据、效果迭代及PR交回约定。

当前文档入口见[文档索引](docs/README.md)。源码仓库不包含真实业务数据、人员账号、密码、附件、历史迁移原件和机器专用部署资料。网页及服务业务代码沿用现有系统；首次启动只建立空库。需要试用时显式创建匿名演示数据，需要迁移现有业务时从受控备份恢复。

登录表单由 HTML 直接提供，背景按屏宽高优先级加载 AVIF（不支持时选 WebP），缩短完整首页的等待；编辑器登录后加载，公开资源按内容版本缓存。业务数据按页面依赖读取，同页复用并合并重复请求，保存后只更新受影响的表；刷新或重开网页仍重新校验并读取当前页数据。维护说明见[页面数据加载](docs/DATA_LOADING.md)，验证范围见[验证记录](docs/VALIDATION.md)。

填报人工作台按来源逐项办理本人事项，住宅／商业共用五部分填报；节点、计划、本人协调及明确分派的会议事项由承办人申请完成或延期，运营管理员（`ops`）统一审核。会议源事项由运营录入并指定单个项目填报人，承办人维护进展；批准延期保留原计划日期，完成按批准后的截止时间判定。填报附件支持图片、PDF、Word 和 Excel，保留报告历史访问与未提交文件管理。项目资料保留档案，预计日期和逐项申报位于工作台；重复项目列表与参考专业流水线已取消。使用及迁移说明见[填报人页面](docs/REPORTER_UI.md)。账号角色与原项目范围沿用，运营新增完成审核入口，领导可在项目详情查看对应反馈、审核记录和附件。

商业填报按账号主专业及当前项目的明确附加授权保存。其他商业项目保留十二个模块，弘坊（`hf`）另有“设计部”，共十三个；运营可给已有弘坊成员明确授予设计部附加专业，同时保留其原主专业。双专业人员通过“我的商业专业”切换，各自维护计划、报告、草稿、附件及AI上下文，旧数据不搬迁。经业务明确授权的 `profiles.biz_line='*'` 仍表示当前成员项目的全部合法模块，不扩大项目范围，也不作为报告模块。旧“土建工程”报告、历史与附件继续只读。普通住宅按分配专业独立确认月计划与提交周进展，原综合、未分配专业及统一范围流程保留。具体规则见[商业模块授权](docs/REPORTER_UI.md#商业模块授权)。

管理员“计划总览”按住宅项目／商业模块横向组织本期填报，汇集同项目多名填报人的内容，展示附件与项目总图。住宅总览按“项目→专业”筛选，商业总览筛选专业，项目及专业区块可折叠；筛选和展开状态仅保存在当前页面会话内存，复用已加载快照，独立月度完成汇总按所选月份读取。总裁使用住宅、商业两类总览；项目总按负责项目开放对应住宅／商业总览，其读取与批示均限主项目或明确关联的项目。旧汇总、经营双维及重复节点归属入口已收敛，评价录入取消，历史评价继续保留。会中交代与批示复用现有项目级记录。总览可打开独立投影窗口。商业默认周例会，只看所选周期对应月份，月度会议时可切到双月。住宅直接使用月度会议。月度会先显示总结、再显示下月计划，两张表各占整行。跟随、暂停和已保存安排的展示方式见[会议投影](docs/REPORTER_UI.md#会议投影与待办口径)。

运营管理员从“计划总览 → 批量导入计划”或住宅／商业总览按钮进入，默认“Excel 直接导入”，选择项目与本月后上传整份文件，无需调用AI即可按正文月份生成本月／下月两个专业预览。默认本月保存独立月度完成情况、下月写入提报人的月计划，可核对并调整选项，最后一次确认在同一事务保存；月度汇总在总览和投影独立展示，不生成周报或完成审核。专业归属按项目与现有授权匹配，上传和核对本身不写入业务数据。可选AI对话、单人手工代填及单月入口保留。计划与本人填报共用，已被周报或申报引用的计划不可修改，原数据、权限和草稿保持。操作及企业样表只测试不真实导入的边界见[管理员月计划](docs/ADMIN_MONTHLY_PLANS.md)。

管理员Excel直接导入和AI整项目上传均允许单件300MiB（页面标为300MB），普通填报附件及员工AI附件仍为单件8MiB。上传放宽不取消ZIP/XML展开量、行数、单元格和解析时限保护；工作簿内嵌图片不作OCR。

深圳上木古住宅与工业共用一个专业汇报入口，保留原项目资料、来源和历史，仍核对完整成员权限。管理员深圳专业目录中的“良安田项目”兼容简称“良安田”，作为独立专业预览，不是新建实际子项目。当前没有匹配提报人，人员保持空值，不能正式保存该专业，也不因此授予员工新的专业写入权限；其他专业及已有计划不变。

项目方案资料提供“项目速览、指标与专题、版本与待核对”，仅检索关键摘录、概要和差异，保留来源物理页码与适用范围。完整原件和整页预览不提供打开或下载；总图只显示经过实际裁剪的关键区域。受控准备工具加密保存原件，读取接口不向浏览器传递全文或原件链接，详见[原件保护与关键摘图](docs/SCHEME_PROTECTION.md)。未整理索引的项目及独立共享资料保留各自功能，源码更新不自动导入真实方案。数据契约见[方案资料中心](docs/PROJECT_KNOWLEDGE.md)。

项目计划统计统一汇总有权查看的住宅与商业基准节点，项目展示组、实际项目和专业／商业模块在同页筛选，卡片、明细与导出使用同一结果。统计分析取消独立住宅节点偏差及商业基准节点明细入口，员工完成统计保持原角色范围；原计划日期、批准延期后的有效截止日和有效审核完成口径保留。

## 本地运行

需要 Docker 的 Linux 容器模式、Docker Compose 和 Node.js 22 或更新的兼容版本。数据库镜像使用 PostgreSQL 17。

```sh
node scripts/setup-env.mjs
docker compose config --quiet
docker compose up -d --build --wait
```

配置脚本生成随机密钥且不覆盖已有 `.env`。默认入口为 `http://localhost:8080`，仅绑定本机。端口已占用时，在 `.env` 同时调整 `APP_PORT` 和 `APP_ORIGIN`。同机部署多个实例时，必须使用不同的 `COMPOSE_PROJECT_NAME`、`APP_IMAGE`、`APP_PORT` 和 `UPLOADS_VOLUME`；`APP_IMAGE`使用独立的本地镜像标签，默认项目名为 `planning-system`。

已有实例增加域名入口时，保留原`APP_ORIGIN`，将额外入口写入`APP_ADDITIONAL_ORIGINS`，例如`https://planning.example.com`；多项用英文逗号分隔。每项必须是完整HTTP(S)来源，不包含路径、查询、凭据或通配符。认证和业务写入使用同一显式来源白名单，原入口继续可用；外站及`cross-site`请求、携带会话Cookie但缺少Origin的写请求仍被拒绝。HTTPS入口设置`COOKIE_SECURE=true`并按代理拓扑配置`TRUST_PROXY`，代理须保留浏览器实际Host和Origin，Cookie按主机隔离。

初始空库没有业务账号。仅在隔离试用实例创建演示资料：

```sh
docker compose run --rm admin npm run seed:demo
```

该命令创建住宅、商业两个演示项目及五个随机密码账号，覆盖提报人、管理员、总裁和项目总四类角色。账号文件位于 `.local/demo-accounts.json`，不会进入 Git。重复初始化不会覆盖已有账号或凭据文件。不要用演示初始化恢复正式数据。

创建新正式账号使用 `scripts/create-user.mjs`，密码通过环境变量提供；具体参数可用 `--help` 查看。原业务账号与历史 UID 应从最新备份恢复，不能凭姓名重新绑定。

账号密码支持 6 至 128 个字符，可使用六位纯数字，不要求字母数字组合；保留密码原字符串与既有较长密码的校验。项目资料的独立下载口令沿用原规则，与用户登录密码分开处理。受控名单、初始密码和账号调整记录不进入源码。

新账号及统一重置后不默认强制首次改密。如需对特定账号启用首次改密，显式设置 `app_private.auth_users.must_change_password=true`，首次登录显示改密弹窗，新密码不能沿用当前密码。未完成改密时，服务器拒绝业务与私有附件的读取和写入，仅允许会话查询、退出及改密等认证操作。验证码登录保留该标记；验证邮箱后设置合规新密码的找回流程可清除标记并注销已有会话。

已授权的全员密码重置使用 `scripts/reset-passwords.mjs`：在核对实例、人数和备份后暂停目标API，通过受限环境提供 `ADMIN_DATABASE_URL`、`RESET_PASSWORD`，显式传入 `--all --database <预期库名> --expected-count <预期账号数>`。脚本在单事务内逐账号生成独立哈希、清除首改标记，并注销所有旧会话、验证码及临时登录锁；不修改账号UID、邮箱、停用状态、角色、项目关系或业务记录。新人员应先按已核对的邮箱、历史UID和授权单独建档，不以重置脚本重建已有身份。

管理查看账号使用 `viewer` 角色，只提供全部项目的事项及项目资料阅读。现有提报人可由运营显式设置 `profiles.management_viewer=true`，保留原角色、项目成员和个人填报范围，同时增加独立的管理查看入口。查看能力不授予统计、审批、分派、上传、撤回或资料口令维护权限；项目资料下载继续要求原独立口令并保留水印与访问记录。人员名单与邮箱映射通过受控流程核对，不随源码迁移创建账号。

已有实例的升级顺序、权限迁移和回退边界统一见[数据库升级](docs/MIGRATIONS.md)，人员调整与密码重置仍需独立受控授权。

## 开发与检查

```sh
npm ci --ignore-scripts
npm test
npm run test:db
npm start
```

`npm start` 需要另行设置受限 `app_runtime` 数据库连接和必要环境变量，启动前会从锁定的 Quill 依赖生成本地编辑器资源。初次体验优先使用完整的 Compose 环境。

测试使用隔离 PGlite、匿名演示资料和 DOM 模拟，不访问线上数据库。涵盖会话、权限、住宅／商业填报、富文本、版本记录、来源变更与审核状态、附件访问及未提交文件配额。完整历史迁移审计与机器专用的云端验收材料不在源码仓库内；源码测试不代替真实数据迁移核对。

提交前执行：

```sh
npm run check:source
git diff --cached --stat
git diff --cached
```

`.gitignore` 使用逐文件白名单，新源码需要同时审阅内容并加入清单。检查器会拒绝不在白名单的已跟踪文件，以及常见凭据、原始数据路径和指定私有环境标记；它不保证发现所有敏感内容。

## 备份与恢复

迁移后的旧实例可设置 `APP_READ_ONLY=true` 和 `READ_ONLY_TARGET`（新的可信 HTTPS 入口），保留登录、读取及下载，拒绝业务修改、上传、审核、注册和改密，并显示迁移提示。该模式采用明确的读取接口清单，新接口默认禁止修改。部署时还应冻结旧实例业务表及可写函数权限、将附件卷只读挂载；认证会话与资料下载授权／访问记录仍需保存。该开关不迁移数据，也不自动同步两个实例，不能通过取消只读直接回切已有新数据的系统。

运行数据位于 PostgreSQL 命名卷和附件命名卷，不在 GitHub 中。

```sh
node scripts/backup.mjs
node scripts/restore.mjs backups/实际备份目录
```

备份脚本会短暂停止**当前 Compose 实例**的 API，制作数据库与附件备份、校验清单，然后恢复 API。先核对当前实例，安排合适的备份窗口。

恢复脚本验证格式、大小与 SHA256，在当前实例的 PostgreSQL 服务中创建**新数据库**和**新附件卷**，不覆盖当前数据；输出切换配置并保存受限说明。先独立验证恢复结果，再按说明切换 API 的数据库和附件卷。已有备份格式保持兼容。

备份、私有配置和附件通过受控加密渠道迁移。最新数据应来自日常使用的业务主实例；本机与云端没有自动数据同步。原始导入 SQL 和旧数据包只是历史材料，不能代替当前业务备份。

更新源码无需删卷。不得把 `docker compose down -v` 当作更新命令；不得用新建空库覆盖现有业务库。已有数据库不会自动重跑初始化 SQL，数据库结构升级需明确执行对应迁移并验证。

新空库按Compose顺序初始化截至035；已有卷不会自动重跑初始化SQL。升级须先核对实际版本、备份并独立验证恢复，再显式应用所缺的顺序迁移及配套服务，见[数据库升级](docs/MIGRATIONS.md)。

## 部署到其他服务器

1. 克隆已确认的源码提交，安装 Docker，单独生成目标环境 `.env`。
2. 根据目标主机配置 HTTPS 反向代理，应用保持回环绑定。设置实际 `APP_ORIGIN`、`COOKIE_SECURE=true`，并按代理拓扑配置 `TRUST_PROXY`。
3. 对已有业务，独立恢复最新数据库和附件，恢复必要配置和账号；新独立系统可空库开始。不要复用本地演示账号。
4. 核对项目、人员权限、住宅及商业保存回填、领导评价、附件和备份恢复，再切换业务入口。
5. 保留旧实例与备份；新系统产生业务后，回退不能覆盖或丢弃这些新写入。

仓库提供通用 Compose，不包含某台服务器的共享 Caddy、网络、域名和覆盖文件。接入已有多站点服务器时先核对原网关和完整 Compose 组合，不能直接覆盖共享配置，也不能以一次 `git pull` 代替正式发布。

## AI填报与记忆

本期填报中的AI助手支持附件整理、多轮对话、本人事项及历史查询、逾期分析，以及预览后本人确认保存本机草稿。对话可刷新续接，个人写法支持查看、修改、删除，按账号、项目、专业及范围隔离。历史建议需重新整理后才可写草稿，模型不能正式提交报告或审批。

管理员可选的AI整项目导入复用计划系统受控 DeepSeek 配置，使用当前窗口约30分钟的临时会话，不读写员工个人记忆，也不承诺刷新后永久续接；未保存预览保留离开提醒。默认Excel直接导入不调用模型，管理员只有点击独立最终确认按钮，才通过受限事务保存所选月计划及月度汇总。

AI使用计划系统独立受限配置，密钥不进入浏览器、源码或镜像。配置、范围、两类会话与隔离验收入口见[AI填报助手](docs/PLANNING_AI.md)。模拟测试不等于真实模型或正式发布验收；实际实例版本及受控发布证据另行维护，旧阶段文档见[历史归档](docs/archive/README.md)。
