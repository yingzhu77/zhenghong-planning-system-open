# 性能审查与验证

本文记录2026-10-29专项审查中已经落地的重复工作优化，当时运行源码限定为 `server/planning-ai-data.mjs` 与 `web/baseline-core.js`，没有新增依赖、数据库迁移、业务数据写入或长期权限缓存。以下测量仅对应该次固定输入与版本，后续功能更新不自动重测或扩大这些结论。实际实例、受控备份及发布结果见私有当前状态入口。

## AI本人事实查询

原加载和返回前核权分别按项目、专业逐条执行SQL。现在把同一事务内的项目／专业参数配对，使用一次批量查询，仍对每一对执行原 `can_write_report` 权限函数；结果只用于本次事务。返回前另开原有身份事务重新读取权限，成员或专业撤销仍拒绝输出。RLS、最终会话核验与个人写法版本复核保持。

固定匿名样本为8个项目、46对项目／专业。加载加返回前复核的权限SQL往返由92次降到2次，权限函数执行范围没有缩减。恢复到独立PostgreSQL的真实运行角色验证中，新旧事实及顺序完全一致；成员撤权、专业撤权与无权锚点均拒绝。交错7轮测量，该局部入口中位数约140毫秒降到99毫秒，总SQL由112条降到22条。未调用模型，此结果不包含模型生成或公网延迟。

## 个人核心基准节点

原每一行节点都会重扫全部报告、解析周期并排序反馈。现在只为本次显示的“实际项目＋节点ID”建立临时索引，一次扫描报告，按原日期、更新时间和报告ID比较。每次渲染重新建立，刷新、修改、撤权重读和本机草稿变化不会复用旧反馈。保留原富文本字段索引、同键首行、当前空白值及草稿优先级；管理展示仍不读取个人反馈。

同一Node VM、固定匿名输入，每份报告20条反馈，先检查状态与HTML一致，再分别预热并各运行3次，中位数如下：

| 显示节点／历史报告 | 原局部渲染 | 优化后局部渲染 | 周期解析次数 |
|---|---:|---:|---:|
| 27／100 | 42.0毫秒 | 3.6毫秒 | 2727 → 101 |
| 100／500 | 742.0毫秒 | 17.3毫秒 | 50100 → 501 |
| 300／1000 | 5049.6毫秒 | 48.0毫秒 | 300300 → 1001 |

40组新旧状态及HTML对照一致。此为局部JavaScript入口测量，不代表正式数据规模、公网整页速度或并发容量。

## 审查边界

权限、月计划撤回、审核及AI记忆的并发守护继续沿用原实现；没有为了减少查询而缓存身份或省略返回前复核。静态内容已有版本URL、ETag和公网压缩，不增加第二套压缩与失效逻辑。附件解析继续使用受限Worker，模型并发和超时不变。

投影及部分旧视图仍需兼容历史周期标签，目前保留读取与本地筛选契约。若以后需要下推日期筛选，应先覆盖旧标签、统一范围、历史来源和权限，不能仅用ISO日期替换全部历史格式。该次未声称完成容量压测，也未调整数据库索引或基础设施。
