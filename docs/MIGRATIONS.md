# 数据库升级

新空库由Compose依次初始化截至035，`db/002-import.sql`保持空初始化，不自动导入历史业务。已有命名卷不会自动重跑SQL；源码、镜像和数据库版本要分别核对。

## 既有实例的升级流程

1. 确认目标项目、实际运行镜像、已应用迁移、数据库和附件卷；读取当前受控状态，保留现有业务身份与来源。
2. 对相互依赖的数据库、角色、上传文件和配置做一致备份并校验离机副本，在独立实例恢复验证；密钥内容不进入源码、镜像或普通日志。
3. 在受控维护窗口按顺序显式应用尚缺的迁移，再定向更新配套API与网页。备份工具如会自动启动API，应先明确维护期间的写入关闭方式，避免中途开放旧服务。
4. 核验健康、权限、住宅／商业保存与历史、富文本、附件、草稿，以及本次变更入口。数据库行、来源、账号权限、独立密钥配置及其他项目服务分别核对。
5. 保留旧镜像和恢复材料。新数据已经写入后，代码回退不能用旧备份覆盖主库；使用能读取现有追加结构的修复版本。

不通过重建空库、演示初始化、删卷或重放人员授权来升级。迁移定义与具体人员名单、密码重置、商业测试授权及正式导入是不同操作，后者必须另有明确授权。

### 后续迁移

035新增私有撤回审计，基于031／033已有保存前后快照恢复整批。撤回在同一事务内重新核对当前授权、统一范围、版本、报告／申报引用，并沿用原确认及填报锁；任何部分不符合条件均不写入。恢复使用新ID，来源及月计划格式保持。原保存实现保留为不可由运行角色直接执行的内部函数，原公开入口增加撤回墓碑校验，旧客户端不能重放已撤回操作。新迁移可重复执行，不迁移或清理既有计划、汇总、报告、人员及授权。升级依赖031／032／033结构；034是既有深圳配置，升级035不重放034。测试默认结构夹具不自动加载034业务范围配置；需要该范围的测试显式建立。

032新增受控附加专业表，管理员通过专用接口明确授予或撤销已有项目成员的附加专业；原主专业、角色和成员关系保持。额外专业按账号、项目和专业验证，撤销只影响该额外范围。新增设计部仅适用于对应商业项目，其他商业项目及住宅目录保持。旧权限函数沿用原owner、ACL与固定search_path，仅按新增专业和明确授权补齐判断，不扩大原固定专业账号。

033将原表完成情况保存到独立月度汇总。运行角色只获受权限约束的SELECT，写入仅开放给管理员的组合保存函数；内部汇总函数不能被运行角色直接调用。组合保存使用同一事务、操作UUID与旧记录ID核对，任何月份或专业失败均回退，重试不能重复保存。原表“已完成”文字不改变审核状态；被引用的月计划仍不允许修改，独立汇总可以单独保存。新接口依赖032/033，必须先升级数据库再启动配套API；回退代码不得删除新汇总或用旧dump覆盖主库。

034仅追加深圳统一范围配置，不修改原项目、成员、专业或计划。已保存月计划与报告包含权威成员快照，不能把新项目直接追加到既有范围数组。良安田目前只是代码中的深圳限定专业目录和别名，不是034追加的第三个项目，也没有新的人员授权或正式写入迁移；以后开放正式填报须同时补齐权限和数据库校验，不能仅修改profile字段。

027之后运行角色仍无月计划UPDATE／DELETE权限；撤回须走原确认人接口，不能直接删除或改写固定列。旧当前／历史报告、任意状态完成延期引用均保留并阻止撤回。新确认使用新身份，私有撤回审计不可用作普通业务读写表。

028仅增加私有记忆能力，按账号、项目、专业、统一范围及周隔离，写法跨周。运行角色使用受控SELECT／INSERT／UPDATE，无DELETE；清空正文保留版本，旧保存不能复活。独立AI配置仍由受限文件提供，数据库迁移不创建或复制密钥。

029在`monthly_plans`追加`report_scope_id`和权威成员快照`scope_project_ids`，同一统一范围、专业、月份只保留一份活动确认版。确认及撤回复核本人专业，撤回仍限原确认人；读取沿用原角色能力，所有操作均复核全部成员项目权限。成员快照不能由客户端指定，已保存计划也不能因范围缩小而绕过原成员权限。明确子项目必须属于该范围，未明确时保留空缺，不将锚点冒认为实际项目。运行角色不增加范围配置UPDATE或月计划UPDATE／DELETE权限。

029的原综合模式每周一份`综合`报告，新报告以`biz.monthly_plan_ids`保存当时全部确认专业计划的引用，每行以`monthly_plan_id`与`source_id`组成来源身份，允许不同专业使用相同`source_id`。保存后引用集合、顺序、固定列和对应富文本保持；后确认的专业计划不自动补入该报告。原来没有多计划引用的报告保留原快照、身份与历史，不自动绑定新计划。030新增专业模式后，原综合模式仅用于已有报告及仍配置为该模式的其他范围。

029使统一范围同月的确认、新综合报告和撤回使用同一事务锁；当前或历史报告的多计划引用及任何完成／延期引用继续阻止撤回。迁移可重复执行，不回填或改写已有计划、报告、审核及账号授权。已有实例需在备份与隔离验证后显式应用029，并同步更新API、网页和只读投影；迁移定义本身不代表目标实例已经发布。

030为范围增加`reporting_mode`：明确启用`professional`的合并项目，在同一入口下按专业独立提报。唯一索引改为范围＋周＋专业，原作者保护和完整成员权限保持；当前专业报告只引用本专业的确认月计划。原分期、综合报告及历史、月计划、附件、记忆、人员和授权不迁移或重写；只更新已确认范围配置。旧锚点同专业报告冲突须明确拒绝自动归入。新的专业草稿与旧综合草稿隔离，旧原文只读保留。

031将月计划唯一身份扩展为项目／范围、专业、月份及确认归属人，专业周报扩展为原身份加作者；原综合范围仍保留每周共享记录。旧记录的字段、作者、确认归属和引用不回填、不改写。管理员使用受控函数为已获批、完整授权的目标提报人保存，实际管理员写入私有审计，运行角色没有对审计表的直接读写权，也没有月计划UPDATE／DELETE权。已被任何当前／历史周报或完成延期申报引用的月计划不可修改，未引用的修正先归档再重新确认；整批事务及操作ID防止部分成功或重复写入。

延期、富文本协调、统一范围、撤回归档、专业周报或记忆产生新记录后，回退版本须兼容这些结构及范围模式，不能只恢复旧唯一索引或旧综合入口。031更改唯一约束，旧API不能单独回退；仅在停写、验证无新业务且新审计表为空时，方可按已审核回退SQL恢复原定义和旧镜像。上线后存在新业务时须保留新数据并修复兼容，不可恢复旧dump覆盖。具体实例迁移、发布及恢复回执存于受控状态；通用说明不替代实际部署核对。
