# 验证与交付

本页说明检查方法及现行验证边界。各批次验证见[历史归档](archive/README.md)，实际镜像、环境及发布回执见受控接续入口。

## 检查入口

```sh
npm run check:source
git diff --check
npm test
npm run test:db
```

先选择与改动风险相关的现有测试，涉及共享契约、事务或权限时再扩大范围。`npm test`是完整流水入口，定向用例通过不能写成全量通过；保留真实退出状态和原失败证据。新文件须审阅并加入精确白名单，不能强制添加私有材料。文档整理只检查文档、链接及源码边界，不重复运行未受影响的应用测试。

数据库或外部服务测试显式使用隔离配置及可丢弃数据，不继承正式环境。事务、唯一约束、锁与权限须用实际PostgreSQL核对。真实模型调用、企业样表测试及正式导入分别记录，不能用其中一种授权替代另一种；独立密钥不进入源码、回复或普通日志。

## 风险与必须保留的行为

| 改动 | 对应检查 |
|---|---|
| 页面读取、缓存与性能 | 固定输入及实际版本；身份、范围、保存失效、撤权、失败和迟到响应隔离 |
| 填报与富文本草稿 | 住宅／商业、固定列、格式、跨窗口冲突、失败留稿与历史来源 |
| 月计划确认、撤回及管理员保存 | 原确认人、完整成员权限、当前／下月隔离、旧版本核对、引用锁、原子保存及幂等回执 |
| Excel解析与分配 | 正文月份、物理源行、表头／合并格、计划日与实际日分离、原完成文字、专业目录及真实授权目标 |
| AI与个人记忆 | 受控来源、返回前核权、候选需本人确认、续接／编辑／删除、版本冲突及旧保存不能复活 |
| 总览与投影 | 商业周例会单月、月度会双月和住宅月度会，历史及专业边界、确认计划完整性、桌面及窄屏排版、暂停／恢复、关窗清理、字号及全屏 |
| 关键总图全屏 | 点击与关闭、同一批准裁剪、焦点返回、匿名／越权及旧原件地址拒绝 |
| 发布与数据 | 正确实例和镜像、受控备份、原卷及数据、权限／附件／环境／独立密钥、其他服务不受影响 |

性能测量注明范围、输入、环境及方法。局部渲染或查询改善不能推算整页公网速度或并发容量；指标见[性能审查](PERFORMANCE.md)。只有新改动、失败或疑点影响结论时才重跑已通过检查。

```sh
node --test tests/admin-plan-import.test.mjs

node --test tests/admin-monthly-plans.test.mjs tests/admin-plan-ai.test.mjs

```

调用这些完整文件可能涵盖多于发布记录中筛选的用例；以本次实际运行的命令、版本和退出结果为准。

## 已知限制与业务边界

- 良安田的专业目录不授予写权限，不能只改账号主专业后宣称能够正式填报。待分配事项须明确处理，不能自动借用工程、设计或原表工作责任人的账号。
- 正文月份与截止日期独立。原表空日期、“持续”、异常年份或跨月截止日保留，不自动补日期或改期；旧确认计划不会因解析器更新被重写。
- 管理员完成情况保存为独立月度汇总，不能伪造周报或自动通过完成审核；已引用计划仍受原锁保护。
- 企业样表的解析、预览、模型识别与正式导入是不同阶段。现存回执未执行的正式导入不能写成已经完成，后续实际业务写入按用户授权另行核对。
- 图片识别后的事项、分类及进展须由本人对照原图确认。优先使用Excel直接读取。
- 进程内AI导入会话及浏览器临时预览不保证跨重启／刷新恢复；本人持久草稿与受控记忆沿用各自流程。
