# 源码管理

本目录用于 Git 版本管理和换机开发。网页、服务模块与既有系统保持一致；通用 Compose、空库初始化、文档和测试样本为源码迁移进行了调整。

## 提交边界

允许提交已审阅的应用源码、静态资源、数据库结构／权限迁移、依赖锁、通用工具和匿名测试。真实业务记录、私有账号、密钥、运行备份、附件、专用云端配置和历史交接材料另行保存在受控存储中。

实名名单、邮箱推导与去重结果、旧身份对应关系、临时凭据及受控导入脚本／回执同属私有材料，不进入源码文档或匿名测试。源码可保存通用认证能力和纯结构／权限迁移，不能把真实人员行、密码重设或账号授权 DML 混入迁移。临时凭据与是否要求首登改密均按受控名单显式处理；新账号与统一重置默认不启用首改标记。普通注册、找回与改密的密码策略仍由服务端统一执行。

`.gitignore` 中的精确文件条目是允许范围。新增文件默认不会进入 Git；使用 `git check-ignore` 确认原因，审阅后添加准确例外。`npm run check:source` 同时核对已跟踪和暂存路径，不能以 `git add -f` 绕过范围。

保护规则无法替代内容审阅。若曾误提交凭据，应轮换凭据并处理历史；仅修改忽略规则不足以撤回泄露。

## 依赖安全维护

使用锁文件安装，更新依赖时核对公告和实际调用，不执行未经审阅的强制修复或主版本降级。当前Quill 2.0.3有上游低风险告警 [GHSA-v3m3-f69x-jf25](https://github.com/advisories/GHSA-v3m3-f69x-jf25)，公告未提供已修复版本。业务编辑器仅允许加粗与颜色，保存受限Delta，服务端拒绝对象embed，展示自行转义；已知formula/video导出利用条件在本业务链路被阻断。Quill内部复制仍可能导出HTML，不能称为完全没有导出调用；新增embed、格式或HTML导出能力前须重新审查。不要按audit提示将2.0.3降到旧2.0.2。

## 与既有业务工程同步

初次源码来自既有业务工程的受控快照，业务资料留在原工程。后续优先在本目录开发；若仍在原业务工程修改，上传前只同步已审阅的对应源码文件，比较差异并检查工作区，不能整体复制原目录。

通用 Compose、空库 `db/002-import.sql`、源码 README、测试匿名数据和忽略规则属于本目录，不能被原工程的真实数据版本覆盖。已有系统的真实导入 SQL、私有部署组合和验收资料继续单独保留。

每次交接记录源码提交、私有备份时间与实际运行版本。服务器可能运行较早的镜像，Git HEAD 不能单独证明线上已更新。

账号切换与源码发布分别留存受控记录。已有实例先备份，按顺序应用所需迁移并更新 API，确认支持首登改密的新 API 健康后再导入核对后的账号、负责项目及固定模块。010 标记默认 `false` 不代表旧账号已改密；011 的项目总范围和012 的十二模块写入规则也不代替具体人员分配。替换账号时撤销旧会话，保留原作者、历史与附件归属，不能凭姓名覆盖真实报告或把旧土建数据自动分拆。

## 换机与换服务器

换电脑先克隆源码、按锁文件安装依赖、恢复需要的受控材料，在独立实例恢复数据库与附件。验证权限和核心业务后继续开发。

换服务器需要额外恢复目标环境密钥、网关、域名、卷名及 Compose 覆盖配置，并安排实际业务主库的最终一致备份和切换。只迁移 Git 仓库不能恢复完整业务状态。

## 文档维护与归档

[文档索引](README.md)指向当前使用、数据加载、AI、数据库升级及验证说明。当前说明描述最终有效行为，不继续追加已经废弃的阶段指令。较早的完整验证和页面口径保存在[归档目录](archive/README.md)，明确日期及历史身份，修正相对链接后保留原证据。归档不代表删除数据库、附件、迁移或受控备份。

源码文档只保存匿名行为与通用操作。实际镜像、环境路径、人员、备份位置、发布回执及未完成项更新项目受控当前状态；其他交接入口引用它。更新前核对并行工作和实际版本，不能将旧历史结论重新覆盖为当前状态。

维护者以项目根目录受控的`接续开发.md`为唯一运行状态入口。该文件及含机器／业务信息的历史快照放在Git忽略的私有目录，不复制进源码归档。公开clone按README和CONTRIBUTING.md独立开发，不要求取得私有文件；公共历史归档仅保留已审阅的通用行为和验证依据，不作为当前线上状态证明。

工作区可能包含尚未提交的受控发布成果。接续时分别核对实际deployment、分层镜像对应的源文件清单、本机差异及迁移状态，不能整体覆盖工作区、只依据Git HEAD部署，或把本机只读入口设置直接复制到写端。文档整理本身不授权重启服务、重新导入、恢复业务库或重放人员授权。
