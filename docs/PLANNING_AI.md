# AI 填报助手

提报人助手支持附件整理、多轮对话、本人数据查询、草稿修改、对话续接和个人写法记忆。入口位于“本期填报”页上方，点击“AI 填报助手”打开居中大聊天窗，手机使用全屏。运营管理员另有整项目月计划导入入口，默认直接读取 Excel，AI 辅助可选。需要模型的两类流程共用计划系统受控 DeepSeek 配置，各自按权限处理，组件与样式按需加载。

实际实例版本与发布验收见受控当前状态；本说明不包含机器配置、账号或发布完成结论。

## 管理员整项目导入

运营管理员从“计划总览 → 批量导入计划”进入，默认“Excel 直接导入”：只选住宅／商业项目与本月后上传整份Excel，程序按正文月份一次读取本月／下月各专业事项、完成标准、计划日期及原表完成情况，不调用模型即可生成两个多专业预览。文件名、实际完成日或跨月截止日不决定事项月份。专业建议可以逐组或一次集中确认，确认只更新预览；人工修改保留，同专业多人仍须明确选择个人。按专业或待确认筛选只改变阅读范围。

管理员直接导入和AI整项目上传均允许单件300MiB（页面标为300MB），只限这两个管理员Excel入口。下文员工助手附件仍是单件8MiB、合计12MiB。管理员工作簿仍受ZIP/XML展开量、行数、单元格和解析时限限制，内嵌图片不作OCR；放宽上传体积不表示任意大表都可被解析或发送给模型。

本月默认只保存独立月度完成情况，下月默认写入各提报人的月计划；可逐月份核对、编辑并调整保存选项，最终一次确认采用同一事务。实际完成时间附在月度反馈中，不能覆盖计划日期；“持续”、多日期和空值不补造。独立汇总在总览与投影展示，不写周报、不建立完成申报或审核结果。需要原单月流程时可选择“仅所选单月计划”。

“AI 整项目批量导入”作为可选入口，支持同页对话澄清。源行覆盖、未处理内容、未确认月份范围和未解归属必须保持可见；范围月份须由管理员明确核对，AI 不能替代确认。原单人“手工代填”继续保留，原高级规则预览已作为默认 Excel 入口提供。

工作责任人与系统填报人分开处理：系统按所选项目＋专业唯一匹配现有授权账号，原表工作责任人仅作参考。弘坊（`hf`）保留主专业，可明确授予独立“设计部”附加专业，项目目录共十三个模块；其他商业项目仍为原十二个。双专业按各自授权匹配，不修改主专业、不搬迁旧计划，计划、周报、附件、AI上下文与草稿继续分开。AI不能因工作责任人姓名不同或空白清空已确定归属，也不能按姓名从多个候选中挑一个。未明确专业、同专业多人或无账号才提示选择。模型问题使用结构化类别，只消解已解决的归属问题；日期、月份、来源及其他真实问题继续保留。

专业工作表与事项子分类分别识别，“专项计划”“一标段”等不会覆盖工作表专业。明确的专业别名自动对应，例如住宅“开发”对应“开发报建”，商业“景观”对应“景观设计+工程”，预览说明对应关系。无法明确对应时仅给出受限建议；点击“确认归为…”或集中确认按钮才更新归属预览，同专业多人仍须再选提报人。按钮确认不等于导入。

深圳上木古住宅与工业沿用同一专业汇报范围；管理员该范围的专业目录中，“良安田”自动对应“良安田项目”，明确的同名工作表归属优先于行内工作分类。它是独立专业，不是新增实际子项目，也不自动归入工程或设计。目前没有匹配提报人，直接导入与可选AI均保留空人员和待分配内容，不能正式保存该专业；目录可见不授予员工写入权限，不修改已有计划、专业归属或草稿。

表格解析保留真实合并区域，区分区域／分项与具体工作；“分项＋完成标准”布局逐行读取具体工作，合并表头下的空占位格不应吞掉该行另一列的真实事项。缺少部分列名时，仅在同一工作表前一明确表头布局能够可靠对应时沿用列位置。中文“月／日／日前”可在明确年月下规范日期；跨月、缺失及异常年份保留原值和提示，不猜测改期，不能按文件名覆盖正文月份。同格多个完成日期完整保留在事项说明，单一完成日期为空，不随意选取其中一天或强迫补造日期。

可选 AI 页在桌面将助手与顶部设置区对齐，手机纵向排列。识别前显示“尚未生成导入预览”，说明它与附件是否有内容不同。该入口选择文件后再点击开始识别，当前范围内可用同一文件重试，等待时显示耗时及取消入口。专业汇总优先显示事项数与待确认归属，未匹配事项可按专业明确整组分配；来源详情默认收起。首次模型服务／网络／超时／输出校验失败时，已解析事项和候选会话保留并提示重试，AI未完成前不能确认该会话；身份、权限、文件或配置错误仍拒绝。默认 Excel 直接导入不依赖模型整理完成。

上传、专业确认、聊天和手动纠正均不写入业务数据。默认Excel双月入口最后点击“确认保存所选月份”，保存明确勾选的月计划及独立月度汇总；单月入口仍为“确认保存所选计划”。可选AI入口的手动纠正先取得服务端候选回执，最后点击“一次确认导入全部计划”，并验证服务端保存的来源证据和候选版本。月计划与提报人共用，独立汇总不改每周反馈；现有权限、引用锁与整批原子保存沿用原规则，不提交周报或执行审核。实际操作说明见[管理员月计划](ADMIN_MONTHLY_PLANS.md)。

管理员会话是当前窗口使用的约30分钟临时会话，绑定账号、登录会话、项目、月份和合并范围，在服务进程内存中保留；不读写员工个人记忆，也不保证刷新后续接。切换范围会取消正在进行的整理并隔离迟到响应，当前窗口保留各范围的输入及旧预览副本。取消或网络中断后可“重读 AI 预览”；如果业务确认实际已完成，应显示保存回执，不能再把它当作尚未导入。新文件识别成功后结束被替代的旧会话，失败或取消不结束旧会话；关闭／刷新前保留未保存提醒。

维护接口与普通提报人助手分开：

| 接口 | 作用 |
|---|---|
| `POST /api/admin-plans/ai/upload` | 上传原始 `.xlsx`；服务端工作线程解析来源后建立候选会话 |
| `POST /api/admin-plans/ai/chat` | 按会话和预期版本继续澄清，返回完整预览 |
| `POST /api/admin-plans/ai/revise` | 应用明确手动纠正或月份范围确认，不保存业务计划 |
| `POST /api/admin-plans/ai/session` | 重新读取当前候选、处理进度及已完成的保存结果 |
| `POST /api/admin-plans/ai/confirm` | 最终明确确认，复用原月计划事务与引用保护；保存回执位于 `result` |
| `POST /api/admin-plans/ai/close` | 结束当前登录会话拥有的临时导入会话，不修改月计划 |

企业原表识别测试只在明确授权范围内进行，测试预览不自动触发正式导入。模拟模型通过不等同于真实模型或业务内容验收；具体证据以受控验收记录为准。

## 使用

1. 选择本人项目、填报周期和专业／商业模块；已有确认计划可填写进展，尚未确认的本月或下月计划可从材料生成候选。
2. 可以问“汇总我的事项”“查询上周周报”“分析本人逾期事项”，也可上传会议记录、进度表或图片说明整理要求。
3. AI 在对话中回复候选进展和来源。可以继续说“第二条删掉”“第一条改成……”。
4. 修改预览明确显示“尚未保存”。核对后点击“确认保存到本周草稿”，或直接发送“确认保存／填入草稿”，两种方式执行同一笔本机保存；看到“已保存……尚未提交”回执才表示成功。可以“查看本周草稿”或“撤销这次保存”；正式提交沿用表单底部按钮。

要求新增月计划时，明确说“提取表内某月事项到本月／下月计划”，无需先有事项列表。候选显示目标月份、模块、具体事项、日期、进展和来源；点击“确认加入某月计划草稿”或回复“确认保存”后，仅追加到当前账号、项目和专业的本机月计划草稿，保留原输入并去重。查看和撤销沿用真实保存回执，已确认月计划的固定列仍不可修改，正式月计划确认及周报提交继续使用原表单按钮。

已打开且获授权的项目，即使当前事项列表为空，也能提取尚未确认的本月／下月计划；不能要求用户先建立事项列表才能新增。明确目标月份、正文月份区块和当前专业后，受支持 Excel 直接由程序提取月计划候选，模型调用为0。候选完整保留具体工作、完成标准及原完成时间；来源仍是工作表和单元格证据，不依赖模型重复转写。

图片月计划走一次受限视觉提取，校验目标月份、当前专业、来源标识、条数及字段后直接生成候选，不再追加第二次模型改写。日期不清时留空并说明，工作文字不清或月份无法确认时返回具体问题，不能猜字或伪造 Excel 坐标。界面明确标为“图片识别”，本人必须逐项对照原图核对；图片识别不是单元格证据验证，不能把模拟响应的测试通过写成真实图片准确率已验收。

长期打开的旧页面若缺少月计划上下文，服务明确提示先保存本机草稿；无法正常保存时先复制当前输入，再刷新页面加载新版。历史附件需重新上传。该情形不表示项目未打开，也不能反复要求“先加载事项列表”；已确认计划或确实无专业权限则分别按原引用锁、撤回和授权流程处理。

月计划候选与已有事项进展候选互斥。保存前重新核对本人权限和服务器确认状态，再比较本机范围、原行与存储快照；其他窗口修改、已确认或读取失败时拒绝覆盖。只写目标草稿，不借本次操作重写其他月份缓存。附件来源行和正文月份由服务端核验；只有文字要求时，事项与日期须能对应本人本轮输入。历史恢复只保留月计划建议文字，不能重放旧候选动作。

可以继续说“把已经保存的第二条AI补充替换为……”“删除这段AI补充，保留原文”。系统按本机来源记录定位，展示修改前后，确认后仅替换或删除对应AI补充，保留原有文字与富文本。手动改过、范围变化或无法确认来源时拒绝自动修改，不清空整行。来源记录随本机草稿恢复，旧版未记录来源的文字不能假定属于AI。撤销仅在这笔内容未被后续修改时执行。

填写已有当月事项进展时，只修改当周进展，不删除事项或修改已确认的模块、名称、完成日期。新增月计划仅限本人未确认的本月／下月本机草稿，不发起完成／延期申报或审批。不能确定事实、月份或归属时，助手应先提出具体问题。模型结果仍需本人核对。

## 本人数据查询

默认当前项目与模块；明确询问本人所有获授权项目时，按本人当前授权范围查询。本人事项包括已确认月计划、专业节点、本人会议事项、独立协调及原周报协调／移交来源，复用原来源身份、旧内容标识及责任人匹配规则，避免周报反复引用月计划导致重复计数。旧项目总安排、总裁交代和未分派领导记录不加入本人待办候选；新会议中明确分派的要求按会议事项办理。旧记录缺稳定来源或当前无法核验会明确列出未计入数量。

合并住宅专业模式下，AI按本人专业周报和原专业授权整理，事实查询可读取本人确认、当前仍获授权的专业月计划。其他专业的确认计划不计为本人月计划；按确认计划标识和原事项标识关联已保存反馈，跨专业同名标识不合并计数。旧综合报告、对话及写法不自动变成本专业内容。服务读取及返回前复核本人专业、原确认身份和完整成员项目快照，撤销任一成员权限后拒绝返回旧范围结果。专业模式及原报告保护见[数据库升级](MIGRATIONS.md)。

历史周报只读取本人当前有权访问的已提交报告，可按项目、报告周一日期范围、关键词查询及比较。过往报告只读；聊天可展开当期正文和事项进展，不展开审计版本全文。逾期以服务端上海日期、当前有效完成审核和已批准延期日期计算，“已完成”文字本身不等于审核完成。未设置日期单列，不猜测逾期天数。原始结果卡显示范围、截至日期、总匹配数与当前展示数；本机未提交文字不纳入统计。

模型只能提出受限查询参数，不能提供SQL；程序重新读取RLS数据、计算数量和日期后再归纳，连续明确查询也不复用旧文字充当新读取。单次每类来源上限1000条，展示最多30条，超过须限定范围，不静默统计部分数据。请求返回前再次校验所涉项目权限。

关闭窗口保留当前页面输入和附件选择；刷新／重新登录后续接服务器保存的已发送文字，附件需要重新上传。已经保存的本机填报草稿及AI补充来源继续独立恢复。新回复使旧候选失效；恢复的历史建议不恢复候选动作或撤销凭据，必须按当前事项重新整理并确认后才能写草稿。历史超过20条、单条12k字符或合计50k字符时明确提示分批，不静默截断。生成后修改目标行或切换范围，旧候选不能保存。AI附件不自动成为报告“附件资料”，需要归档时仍用原附件区。

## 对话与个人写法记忆

在AI窗口点击“对话与记忆”查看、修改或删除当前对话及个人写法。对话按账号、项目、专业／商业模块、填报周、统一范围及其权威项目集合隔离；个人写法在相同账号、项目、专业及范围内跨周使用。其他账号或专业不能读取该内容；有权管理员的业务查看能力也不开放员工个人记忆。

仅持久化已发送文字和本人明确保存的写法，不自动从AI回复学习，不保存附件、候选动作或操作凭据。写法最多1500字，用于表达顺序、语气及常用措辞；进展、日期、负责人、审核等事实仍以当前业务记录为准。模型每次读取当前写法，修改或删除后不能套用旧写法的迟到结果。

对话可编辑／删除条目或用“新对话”清空当前范围；原未发送输入、附件选择和填报草稿保留。删除后保留空内容版本，旧窗口及迟到自动保存不能复活已删正文。保存失败保留输入，版本冲突须重新读取后再保存；明确撤权后隐藏已缓存记忆，网络失败不能被解释为空记录并覆盖。疑似密钥拒绝保存。已有实例需要应用028迁移，升级要求见[数据库升级](MIGRATIONS.md)。

## 附件范围

本节描述提报人助手的附件整理；管理员整项目 `.xlsx` 的受控证据与临时会话另见上节及[管理员月计划](ADMIN_MONTHLY_PLANS.md)。

- 最多4件，单件8MiB，合计12MiB；按实际文件内容验证格式。
- PDF：提取文字与真实页码，最多30页；无文字或扫描页明确要求转图片上传，不冒充OCR成功。
- Word：`.docx` 正文文字，内嵌图片需单独上传。
- Excel：`.xlsx` 按工作簿真实关联读取工作表和单元格坐标，正确区分空单元格与共享字符串，按原日期样式解析日期并保留真实合并区域；只读缓存原值，不计算公式。明确月计划提取时，受支持的目标月份和当前专业直接形成候选，无模型调用；未知内容仍需核对。
- 静态 PNG/JPEG/WebP/GIF：通过支持视觉的模型识别。月计划使用上述单次事实提取并标明须对原图核对。旧 `.doc/.xls` 请先另存为新格式。

解析在独立 Worker 中执行，最多10秒、256MiB堆、6万字，复用原有受限ZIP/XML与图片校验。附件解析内容仅在请求内存中使用，不写业务附件库或服务器会话文件；已发送文字与明确保存的写法按上方记忆范围存入私有表。附件内容不会成为跨次对话记忆，需使用时重新上传。

## 本机服务配置

Node.js >=22.13，锁定新增依赖 `pdfjs-dist@6.4.299`。参考既有 DeepSeek Responses 接入方式；计划系统使用独立服务密钥与受限JSON，不与其他项目混用密钥，浏览器不接触密钥。管理员整项目 AI 导入复用这份计划系统受控配置，不要求把密钥填入导入页面，也不复用员工个人写法或对话记忆。

```json
{"enabled":true,"api_key":"在本机填入服务密钥","model":"deepseek-flash"}
```

以环境变量 `PLANNING_DEEPSEEK_CONFIG` 指向该文件，不将JSON、密钥或实际路径提交Git。Unix权限必须为600；Windows通过ACL限制为运行用户和系统。必须使用 `deepseek-flash` 才能处理图片。没有显式配置时返回明确的503提示，不伪造整理结果。需要模型的请求将对应解析内容发送到配置的DeepSeek服务；默认管理员 Excel 直接导入和受支持的员工 Excel 月计划提取不发起模型调用。

服务只连接固定DeepSeek地址，不继承其他项目专用中转或配置。每用户同时1次、总同时4次模型整理；HTTP大请求在读入前额外限制接收并发。每次模型请求最多45秒，提报人事实查询至多两次模型调用，支持取消，不自动重试。非约定JSON、未知事项、伪造来源、额外固定字段均拒绝。请求前后检查原项目、模块、住宅统一范围权限，返回前重新校验会话及强制改密状态。模型整理请求不写报告或执行审批；管理员只有通过独立最终确认接口才能保存受限月计划。

官方依据：[Responses API](https://api-docs.deepseek.com/api/create-response/)、[多模态与会话格式](https://api-docs.deepseek.com/guides/responses_api/)、[PDF.js Node 示例](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs)。多轮历史助手消息保持完整 `{reply,draft}` JSON，与系统输出契约一致；不要将展示文案和预览数组拼成上游助手消息。
