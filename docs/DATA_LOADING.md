# 页面数据加载

## 页面切换与编辑器布局

富文本仍在本次页面渲染内完整初始化，先在脱离文档的容器中建立 Quill 和原 Delta，再批量放回各输入位置，避免每个编辑器初始化都触发整页布局。原输入 ID、文本与格式绑定、只读／禁用状态、输入法和选区工具栏保持同一契约；离开页面前仍捕获并保存原范围草稿，不延迟到离开后初始化或保存。

普通自适应文本域批量重置高度、读取内容高度后统一写回；已被富文本替代的隐藏源文本域不测量高度。此次只减少渲染过程的布局计算，不增加业务缓存，不改变请求依赖、权限校验、保存失效和迟到响应隔离。

管理查看使用独立的 `ManagementReader` 组件和 `/api/management-read` 只读接口。纯查看人不加载个人工作表；获得查看能力的提报人保留原个人数据缓存、项目、周期及条线。管理页独立保存项目筛选、分页和档案分类，不把全部项目写入个人 `S.projects`、报告、任务、审核或填报范围。接口在专用事务内设置管理读取上下文，结束事务即清除；普通接口继续执行原项目及承办范围。

协调页合并独立申请与北京时间当前周的报告协调／移交，保留真实来源项目；多项目报告未指定实际归属的事项明确显示未指定，不推断为主项目。完成／延期页展示申请时快照及审批历史，不把旧申请当作当前来源有效状态。会议、申请与协调按服务器稳定游标分页，页面标明已加载与更多记录。档案按所选实际项目加载七类资料；共享资料只列项目元数据，再复用口令、水印下载接口。管理读取失败、换范围、退出、能力撤销或迟到响应均不恢复旧范围内容。

`web/app.js` 的 `pageDataKeys()` 列出各导航页与详情页签依赖。原业务表仍读取当前账号经服务端授权的完整表快照；会议、完成审核和填报附件使用受限专用接口，分别保留本人范围、分页／来源范围和报告范围，不能把局部结果冒充完整表。

普通提报人的页头还需要项目成员与填报记录，用于项目范围和历史周期选择。以实际 `pageDataKeys()` 和回归测试为准；页面新增统计、下拉框或导出字段时应同时检查间接依赖。

同一已登录页面内，表快照保存在内存，已加载表复用，正在进行的同表请求合并。手动“刷新数据”只读取当前页所需表，同时将其他已访问表标为待更新，下次访问时重读。保存只强制更新受影响的表，其他页面复用更新后的快照。失败不记为成功空表，页面保留明确错误提示，可主动刷新重试。

刷新浏览器或重开网页后内存重新建立，仍从服务器读取当前页数据；没有把企业业务快照持久化到浏览器。已有本机草稿功能继续独立运行。

登录启动可复用刚从认证接口取得的本人资料；密码登录返回未含资料时仍读取本人资料。退出、会话失效及下一次登录会清除读取状态；旧账号未完成的请求不能恢复到新账号快照。保存期间失效的旧读取结果也不能覆盖新快照，较早的页面请求不能抢先渲染后一次导航。

认证接口的 `session.user.must_change_password` 为真时，先按需加载首登改密组件，完成改密前不进入业务资料读取。`POST /api/auth/change-password` 成功后返回同一身份、标记已清除的会话，再恢复原页面启动流程。服务端统一门禁同时拒绝待改密账号的业务 API 与私有文件访问，前端弹窗不是唯一限制；退出或会话切换后，迟到的改密响应不能恢复旧身份。

API继续 `no-store`，每个实际请求仍由服务器认证与PostgreSQL RLS校验。按需加载与内存复用不授予权限，也不改变现有角色和项目范围。浏览器中已有页面不会自动获得其他用户的最新修改，手动刷新或重新打开可读取最新授权数据。

验证入口：`npm test` 包含页面渲染对照、请求合并、失败恢复、保存竞态、退出后迟到响应和手动刷新范围。真实浏览器验收使用隔离匿名账号；正式环境只读验证与部署记录放在私有运行工程，不进入源码仓库。


## 专用读取范围

填报人会议列表不携带每条任务累计历史。完成申请列表由服务器按项目和审核状态分页；列表显示已加载范围及后续游标。填报端另按可见来源标识分批补充审核状态，用于节点与事项上的准确状态，这些记录不加入主分页队列。按来源补充读取不完整时报告错误，不能据此认定事项没有审核记录。清空运营状态筛选时明确请求全部状态，不退回服务端默认的待审核。

填报页附件列表按本人、项目、周期和模块读取；报告正文／历史按可读报告读取附件元数据。先完成所依赖的项目／报告等基础读取，再确定这些专用查询的范围。新增附件或切换项目、周期、详情页签后，不能复用另一范围的列表。附件二进制由受限接口按需加载，图片缩略图使用懒加载，不在业务列表中返回文件内容。

显式授权账号的 `profiles.biz_line='*'` 只表示可选择十二个真实模块，不能用 `*` 查询或上传附件。填报范围使用当前实际选择 `S.pmLine`，报告、本机草稿和跨期同步反馈也按该真实模块区分；固定模块账号仍固定，未分配账号不发出可写商业范围的附件请求。切换模块先保存原范围草稿，再读取目标模块附件并回填该模块报告，保留其他模块的正文与附件选择。项目、周期或模块切换后的迟到响应不能覆盖新范围。旧未拆分的“土建工程”仍随授权历史读取，不能作为新的可写范围或上传范围。

计划总览读取当前住宅／商业范围内本期报告的附件元数据，二进制仍按需加载；同步反馈直接使用报告已保存快照，不为总览新增完成审核查询。项目详情正文／历史保留对应只读同步反馈、审核与附件模块；运营完成审核页单独加载审核模块。填报人任务模块、条线样式、项目资料模块继续按页加载，七标签只渲染当前标签。模块加载成功与数据读取成功分别判断，不能用空模块代替完整内容。

计划总览的住宅项目筛选、商业专业筛选及项目／专业折叠只操作当前授权快照，不增加页面依赖或业务请求。`S.overviewUI` 仅在当前页面会话内存保存选择与展开状态，退出、换身份和重开网页后重建；不写入浏览器持久业务快照。筛选前捕获未保存的工作要求，返回原专业时保留输入；保存仍针对完整项目同类记录。项目总的可选项目还受服务端主项目／成员项目 RLS 限制，不能用前端筛选扩大范围。

## 保存与失效

- 填报提交后更新报告、对应审核状态和附件列表，再进入历史页；历史页按其报告范围重读元数据。取消当前附件引用不会删除旧报告的引用关系。
- 完成申请／审核操作后重读审核状态；涉及节点通过或重新打开时同时重读节点，更新工作台与原偏差计算。
- 节点日期、说明或归属保存后重新核对关联审核状态；读取失败时，已修改的来源不能继续按旧审核结果销项。切换填报项目／周期后先读取新范围的附件，再恢复该范围草稿。
- 显式测试账号切换商业模块时复用同一会话已授权的项目等基础表，只重新建立目标模块的表单／草稿与附件范围；同步来源刷新也核对模块作用域。运营变更账号模块配置后，账号刷新或重新登录，保存与专用接口仍由服务端按当前授权核对。
- 会议保存重读本人会议与审核状态；手动更新同步来源重读报告、领导安排、本人会议和审核状态，不重读无关档案。
- 附件上传／丢弃更新当前附件元数据及选中 UUID，保留正文和本机草稿；原图／PDF下载不触发整页业务重读。已引用文件不能通过丢弃接口删除。
- 原主数据、分期、图纸及报告局部保存继续更新各自受影响的数据。手动刷新当前页时，其余已访问范围标为下次更新。

专用查询沿用会话隔离、请求合并、范围／版本失效与失败提示。分页响应、来源刷新和上传响应在退出、换账号或换范围后不能恢复到新页面；浏览器重开仍从服务器获取当前授权数据。本机填报草稿只额外保存附件 UUID，没有新增持久业务表快照。

详细行为及数据库升级见[填报人页面](REPORTER_UI.md)。

模块、项目或周期切换先保存原范围，再移除原表单；加载期阻止提交、上传和再次切换，自动保存须匹配原范围及会话。更新同步来源在读取前后捕获完整表单，来源读取迟到或失败也不能覆盖新范围或丢失等待期间输入。

管理员七分类档案通过 `ensureAdmin()` 按需加载管理 JS／CSS，并复用填报端档案展示资源。保存当前分类的字段补丁，保留其余分类及未知字段；主数据、分期和图纸分别更新自身快照，总览使用更新后的图纸数据。项目与分类切换前捕获当前编辑，失败不清除未保存内容。

会议布局的计划总览在每个专业内将多作者报告合并成核心节点、当月计划、协调及移交四张表，行内保留作者来源，各报告历史、同步反馈和附件继续独立可读。住宅空专业区块还使用已加载的人员与项目成员关系，不增加额外业务表或持久缓存。专业工作要求仍保存为项目级领导交代，按文字前缀分区显示；编辑、删除保持全项目草稿原索引，保存完整项目同类列表，保留其他专业和无前缀／未知前缀旧记录。

## 运营会议、延期及实名协调

`projectPeople` 在项目／成员基础资料之后按当前项目读取 `/api/project-people/list`，仅返回有效相关人员的身份、姓名、角色和专业；同项目访问复用，项目切换及项目／成员更新后失效，退出清空。源组织数据继续用于旧记录间接匹配，不再作为新协调下拉。会议页按需加载任务组件，运营列表与填报人本人列表由服务器分权。项目总页头及详情间接依赖project_members，不能仅凭profile主项目推导全部负责项目。

延期与完成共用分页和按来源补充读取，按记录ID去重；同一来源的多次延期不覆盖完成记录。期限批量关联，避免逐行新增期限查询；批准延期后仅刷新相关审核状态，工作台执行日期从新快照计算，原计划基线不变。总览右栏附件复用报告元数据，图片懒加载，专业筛选不新增业务查询。

## 管理端项目统计与阅读

项目计划统计页按需加载独立组件，通过只读 `/api/project-plan-statistics` 在原身份及项目 RLS 下读取。默认统一纳入当前有权查看的住宅与商业基准节点，不再提供住宅／商业切换；商业来源仍为基准节点，不使用确认月计划作为分母。项目展示组与实际项目／分期包含两类有权项目，专业／模块按各节点所属项目确定；同一展示组不扩大实际项目权限。卡片、项目对比、明细和导出使用同一服务器筛选结果；条件改变、刷新、来源数据更新或换会话后旧结果失效，读取失败不显示旧筛选的统计。

住宅总览先按展示组汇总，再按专业合并表格，每行保留实际项目／分期。会议、详情、历史、附件与保存继续使用原项目及来源标识。图文对照复用当前有权项目总图和本期报告引用的图片，分栏、切图、缩放只改变页面阅读状态，不新增上传、持久化快照或编辑职责。统计分析菜单集中使用项目计划统计与原角色可用的员工完成统计，取消独立住宅节点偏差和商业基准节点明细入口；总裁及项目总保持项目统计只读权限，维护和审核入口仍按原职责提供。

## 住宅专业、会议投影与AI记忆

住宅总览按项目展示组后继续按专业筛选，未明确归属单列。已确认但尚未提交本周报告的专业月计划仅补充只读预览，不计入已提交数，不补入历史周期。项目／专业筛选复用当前有权快照；切换前捕获未保存安排，投影暂停和明确选择已保存记录后展示保持独立。投影消息只传展示选择及已保存标识，由只读窗口自行读取并复核权限。商业周例会沿用所选周期的报表和对应月份的计划，可读取该月独立汇总。月度会议读取所选总结月的汇总和随后一个月的完整确认计划。关闭子窗结束会话，刷新子窗可恢复连接。

AI文字对话和个人写法使用专用记忆接口，并按账号、项目、专业、周及统一范围隔离；写法去掉周维度。它们不是页面业务表缓存，也不替代本机填报草稿。恢复的历史建议不能直接写草稿；编辑、删除和保存采用版本冲突处理，退出／撤权后的旧响应不能恢复个人内容。详见[AI填报助手](PLANNING_AI.md)。

员工附件读取按真实XML单元格结构识别空格、共享字符串、日期样式与合并范围；新月计划候选复用管理端的受限来源读取，不再从已确认事项列表反推是否允许新增。本人未确认的本月／下月草稿单独进入模型上下文，服务端核验授权、确认状态和来源，明确确认后才写入本机目标草稿。聊天输入不触发表单自动保存；未改动的已缓存月稿不重写，修改过的月稿只有存储原值未变时才保存，防止旧缓存覆盖其他窗口的输入。

## 管理员整项目 AI 导入

管理员导入使用独立的 `AdminPlans` 页面状态，不切换登录身份，也不借用提报人的本机草稿。页面按需加载管理组件，并复用 `planning-ai.css` 的对话样式及现有富文本编辑器，不加载员工对话记忆来承载管理员导入。

默认Excel批量流程只选择项目与本月／会议汇总月，一次读取本月计划及完成情况、下月工作计划；AI是独立可选入口。`/api/admin-plans/context` 返回当前账号可用的项目、专业／模块、具体提报人组合、旧计划和独立汇总。`project_professions`还可列出项目限定的待分配专业，这不是可保存目标或人员授权；深圳良安田没有owner时继续保留待分配。专业与人员筛选用于手工代填和纠正，规则、AI、手工及不同月份输入按各自范围保留，不能因新增目录或切换入口而重写另一范围内容。

总览和投影通过`/api/monthly-summaries?month=...`读取独立月度完成情况，按月份建立读取状态，失败不能记作成功空表。汇总与每周报告分开展示，保存所选月份后按相关范围刷新；它不是每周进展或完成审核的替代来源。商业附加专业通过专用授权目录读取，保留原主专业及按账号／项目／专业隔离的草稿；目录读取失败不能静默切回其它专业并覆盖输入。

规则与AI预览共用“项目＋规范化专业”的授权目标匹配。工作责任人保留在来源中，不参与账号查询或姓名匹配；唯一专业候选自动归属，多人／无候选／未知专业保持待选。高级规则按专业集中分配，不按原表责任人拆组。AI模型中的工作责任人标为只读参考，服务端归属仍以现有授权目录及明确人工修正为准。

专业同义词由一个共享模块维护；已明确的工作表专业优先于事项子分类。未知专业的模型建议与真实分配分别返回，按钮确认通过现有候选修正接口更新版本，不直接写入计划。缺列名仅在同表已核验表头结构能对应时继承列位置，保留真实合并锚点与逐行工作内容；跨月日期和异常年份只提示核对。

AI模式只缓存所选File对象到当前范围内存，明确开始后才请求，不将企业文件写入本机持久缓存。识别等待显示真实耗时；专业汇总、待确认分组、专业／待处理筛选与分页复用完整候选，不新增业务读取、不缩小最终保存集合。来源说明默认折叠，手动整组分配仍走候选修正接口，取得新版本回执后再确认。

AI 上传先在隔离工作线程中解析完整工作簿证据，再由服务端建立绑定账号、登录会话、项目、月份及合并范围的临时会话。聊天和手动纠正按候选版本更新预览，不写月计划。源行覆盖、未处理内容、明确排除原因和未知月份范围都随当前候选返回；只有管理员明确核对范围，且未解问题与来源覆盖满足要求后，才可确认。浏览器不能在最终确认请求中重造来源或另传一份事项替换已核验候选。

首次受限模型服务故障可返回`ai_status=needs_retry`及固定脱敏`ai_error`，原解析候选与会话保留，`complete=false`、`can_confirm=false`；继续聊天成功后清除故障状态。返回原文前重新核对登录、账号和完整范围授权，失效身份、撤权、改密、取消或无效来源不能降级成可读预览。已有对话失败保持原候选及版本，不能用失败内容覆盖它。

临时会话约30分钟保留在服务进程内存，不属于员工个人记忆或持久业务缓存。窗口中的输入、预览及最近只读副本与正式数据分开；浏览器刷新或服务重启不保证恢复，关闭前保留未保存提醒。新文件识别成功后结束被替代的旧 AI 会话，失败或取消不结束旧会话。AI 默认预览为只读表格，高级纠正按页挂载富文本控件，每页20行；最终保存仍包含全部已选专业与事项。

切换账号、项目、月份或录入方式会取消当前整理，迟到的读取和解析结果不能进入新范围。取消或网络中断不能证明服务端未处理；后续通过 `POST /api/admin-plans/ai/session` 重新核权并读取当前候选。已完成业务确认的会话通过 `confirmed` 和 `result` 返回保存结果，前端按 `result.plans` 回填，不把顶层旧计划列表当作新保存回执。

最后一次确认仍由后端重新核权、校验旧计划ID、引用状态和操作标识，复用原月计划整批事务；成功后刷新月计划与对应审核状态，其他页面使用更新后的快照。确认请求的网络取消不等于事务回退；同一操作重试应返回原回执，不重复建立计划。手工代填及高级规则入口仍走既有受控保存接口。

本人周报与月计划查找包含作者／归属人，旧综合范围仍读取原共享记录。草稿中的`monthlyPlanReferences`仅用于本机识别确认计划是否已被替换，不进入周报业务正文或API；发现新计划ID时保留原草稿并要求明确核对。未带版本信息的旧草稿只根据时间提醒，不自动删除；外部确认下月计划也不清除本人原编制草稿。详见[管理员月计划](ADMIN_MONTHLY_PLANS.md)。
