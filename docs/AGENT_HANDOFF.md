# 可直接交给开发 Agent 的提示词

你负责接续开发计划系统，让我在本机看到实际运行效果并据此调整。源码仓库：https://github.com/yingzhu77/zhenghong-planning-system-open 。请执行以下约定，先完成安装、启动和预览，再根据我补充的需求／截图开发；常规必要步骤自主推进，遇到确实缺失的信息集中询问，不只交付方案。

1. 默认中文。先读AGENTS.md、README.md、CONTRIBUTING.md及相关文档，核对目录、分支和差异。新目录克隆仓库，从最新main建立`codex/任务名`分支；已有目录先保留本地成果，不能覆盖、清理或强推。公开clone没有私有的接续开发.md，不需要索取生产材料。

2. 检查本机Git、Node.js 22.13或更高兼容版本、Docker及Compose，Docker须支持Linux容器。缺失时用官方来源安装并核验；确需管理员权限、系统重启或用户操作时，一次说明具体原因与步骤，同时继续不依赖该操作的工作。不要修改其他项目服务或使用付费资源。

3. 在仓库根目录执行`npm ci --ignore-scripts`和`node scripts/setup-env.mjs`。配置仅供本机使用；同机多实例须分别设置`.env`中的`COMPOSE_PROJECT_NAME`、`APP_IMAGE`、`APP_PORT`、`UPLOADS_VOLUME`，并让`APP_ORIGIN`匹配本地端口。保留回环绑定，禁止复用正式配置或连接正式数据库。

4. 执行`docker compose config --quiet`、`docker compose up -d --build --wait`。拉取的是完整源码，首次数据库为空，还须执行一次`docker compose --profile tools run --rm admin npm run seed:demo`建立匿名住宅／商业项目和演示账号。账号随机密码仅在本机`.local/demo-accounts.json`；告知我文件路径，不将密码写进回复、截图或提交。重复启动不重复初始化；不得删卷解决初始化问题。

5. 主动打开本地预览（默认`http://localhost:8080`），完成真实登录并查看相关页面，给我可访问地址。若当前页面缺少测试内容，使用本地匿名样本补齐必要角色、计划、汇总或长短文本等测试状态；不得导入真实企业资料、伪造业务结论或用静态假页面代替真实保存。可复用的测试数据用单独脚本管理，不混入正式迁移。

6. 按我的反馈迭代到可检查效果。前端或服务代码变化后执行`docker compose up -d --build --wait api`，保存输入后刷新查看；检查桌面／窄屏、长文本、空状态及关键操作，界面排版根据内容调整。使用真实页面截图说明结果，不以接口成功或测试数量代替实际观看与业务核对。

7. 采用现有架构和锁文件，保持住宅／商业差异、账号身份、项目／专业权限、富文本、来源ID、历史记录及撤回保护；不猜测人员归属、不降低权限校验、不绕过冲突和引用检查。小范围解决实际问题，不顺带重构无关模块。涉及业务口径、数据损失或明显范围变化时先说明并确认。

8. 先复现，再修改，再用相关测试和实际入口验证；涉及保存须刷新回读，权限／旧数据／并发按变更风险覆盖，数据库测试使用独立匿名实例。浏览器夹具使用Edge，缺失时按指南安装，不能跳过后称通过。保留有效断言，不关闭规则或掩盖失败；没有新变化或疑点时不反复运行已通过检查。结构变化说明迁移、兼容及回退影响，不将`docker compose down -v`用于日常更新。依赖升级先查实际公告与调用，不执行强制自动修复。

9. `.gitignore`是逐文件白名单，新文件审阅后加准确例外，禁止强制加入业务目录。真实数据、账号、密钥、`.env`、附件、备份、私有交接及演示凭据不入Git。只暂存本次修改，提交前执行`npm run check:source`、`git diff --check`并审阅`git diff --cached`；提交信息说明具体结果，避免混入无关改动。

10. 效果达到要求后推送开发分支并向原仓库main提交PR，不直接改main。没有写权限时Fork后向原仓库提交PR；需要GitHub登录时使用我的本机授权，不索取生产密钥。PR写清问题与行为变化、匿名效果图、复现和验收步骤、实际通过／失败／未验证项、提交编号及升级影响。更新现有说明，不复制多套“当前状态”。

11. 最终交付本地预览地址、PR链接、最终提交编号和简短验收说明，等待我确认效果并将PR交回原维护窗口。由原维护Agent核对最新运行版本、审查与必要修复、完成相关验证后合并并按已授权流程部署；你不操作线上、不自动合并或部署。代码推送、本地通过和实际上线分别报告，不声称未经验证的结果。
